## Monitoring that does something

Dashboards that only page a human are a half-finished system. Once Prometheus
and Grafana were covering both infrastructure and application metrics, the
obvious next step was to close the loop on the alerts whose fix is always the
same.

The canonical example: server disk usage crosses 70%. Instead of paging me, the
alert fires a webhook that triggers a Jenkins pipeline which prunes the oldest
backups and cleans out the Jenkins workspace directories. The incident resolves
itself and leaves an audit trail of what ran and why.

The rule I applied when deciding what to automate was simple — if the runbook
for an alert has no decision in it, it should not need a human.

## On-call

I also hold the production on-call rotation for the platform's servers, which
is a strong incentive to keep expanding the set of alerts that fix themselves.
